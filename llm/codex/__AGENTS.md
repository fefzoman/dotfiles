# Agent Policy

Make the smallest complete change after tracing callers. Reuse existing code and tools; add no speculative features or dependencies. Preserve correctness, security, trust-boundary validation, data-loss prevention, accessibility and error handling.

- Skills and general plugin policies are opt-in. Reuse active instructions; load additional procedures when named. Before committing more than about 30 changed code lines, use @ponytail-review (config/generated files excluded). Comments explain constraints in at most two lines.
- For small explanation tasks, read the named file directly and answer from it. Expand only for a specific unresolved question that affects the answer; bound searches by path and result count. Stop when the requested behavior is explained.
- Automatically apply `code-retrieval` before any information retrieval, including code, files, documentation, web sources, and connected data; read `skills/code-retrieval/SKILL.md` relative to this global policy once per session. Use the smallest useful source search or read; for local code, use bounded `rg` + `sed` for known identifiers/ranges and smart-read for behavior discovery or unclear structure. This skill is an exception to the opt-in rule. Reuse completed reads after interruptions.
- Run `smart-read index` only on explicit request, in the foreground; monitor until exit and stop on cancellation.
- For unresolved unfamiliar/version-sensitive APIs, check the project's pinned version and installed source/help, then matching official documentation. Verify the source version; report unresolved gaps. Local search does not replace API evidence. Do not require MCP, credentials or sign-in.
- Use natural-article for substantive documentation. Superpowers brainstorming, plans, worktrees and subagents run only on request; keep plans inline unless a document is requested. Priority: user requirements → agent policy → Superpowers defaults.
- Keep model, effort, tools, plugins and skills stable during a conversation; apply configuration before a new session. Ponytail is enabled; Superpowers is opt-in; DLM belongs in work profiles. Never suggest changing model/effort mid-session.
- Use RTK for supported noisy commands; automatic rewriting requires a verified hook. Keep searches/logs narrow. Recover hidden details with `RTK_DISABLED=1` and verify the source. Discover tool names before schemas; emit MCP `content`/`isError` without duplicate structured data. Return shell status, session ID and relevant output; save large logs locally.
- Retain running process/session IDs and use native waits (about 30 seconds, then 60 if unchanged); preserve cancellation and exit status. Report changed progress or completion.
- Run narrow validation, review the final diff and remove unnecessary comments. Commit regularly with the repo's prefix convention; no AI attribution. Report changes, checks and material limitations. If a tool is unavailable, continue with built-ins.
