The type, tokens, and components behind Linux fieldnotes. Use this page as the reference for new HTML files and for reviewing changes to existing ones.

A reference that stays in sync

Use this page when creating or reviewing another lesson. Its examples load the same CSS, theme loader, and JavaScript as the articles; the values below come directly from the active CSS variables.

Typography follows the system-font approach of The unreasonable effectiveness of HTML: serif headings, italic emphasis, a sans-serif reading face, and monospace annotations. Colors and lesson controls retain this project’s approved design.

Keep the explanation visible. Use ordinary lists, tables, and diagrams; reserve disclosures for optional answers. Do not add interactive walkthroughs.

Figures & responsive layout

Use purpose-built inline SVG when spatial relationships matter: connected trees, labelled boundaries, branching flows and timelines. Reuse the vector-diagram styles and theme tokens. Include an accessible title and description, keep explanations visible, and let wide diagrams scroll locally on narrow screens rather than shrinking labels beyond readability.

On a phone, the article remains one column. Tables and code may scroll inside their own containers. The entire page should not scroll sideways. A collapsed sidebar retains a small reopen control.

Use this design in another file

Use this file as the visual reference and an approved lesson as the conversion template. Reuse the shared assets; do not copy specimen content into a lesson.

<script src="assets/theme.js"></script>
<link rel="stylesheet" href="assets/lesson.css">
<script src="assets/lesson.js" defer></script>

The theme loader precedes the stylesheet. The deferred lesson script initializes the header and sidebar controls. Keep the required control IDs, accessible names, and theme-color metadata when reusing the shell.

The page-specific assets/design-system.css and assets/design-system.js only render this reference and its live token values. Regular lessons do not need them.

For the conversion workflow, see the Markdown-to-HTML skill. Its saved scripts preserve source content and test the result without executing the command examples.
